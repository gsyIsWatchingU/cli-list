# 文档维护规范

## 文档职责

- `README.md`：面向使用者，说明项目能力、安装和配置方法。
- `docs/work-roadmap.md`：记录已经完成的开发里程碑与验证结果。
- `docs/feature-list.md`：维护功能状态，作为能力清单的事实来源。
- `docs/plan-list.md`：维护优先级、下一步和阻塞项。
- `docs/doc-maintenance.md`：维护本文档体系的更新规则。

## 更新时机

- 功能发生变化：更新 `feature-list.md`。
- 完成一次有效开发：追加 `work-roadmap.md`。
- 优先级或下一步变化：更新 `plan-list.md`。
- 安装方式、项目定位或公开能力变化：更新 `README.md`。

## 开发结束检查

1. 执行 `.\test.ps1`。
2. 检查功能清单与实际代码一致。
3. 记录本次改动和验证结果。
4. 更新下一步计划与阻塞项。
5. 确认没有提交本机配置、密钥、临时截图或构建产物。

## 格式规范

- 文档使用简体中文，命令、路径、字段名和产品名保留原文。
- 内容保持精简，不建立重复职责的说明文件。
- 开发记录按日期倒序维护。

## 固定收尾提示词

> 完成功能后，执行测试，并同步更新开发记录、功能清单和后续计划；只有外部使用方式变化时才修改 README。
